01 / The approach

More perspectives.
One research question.

A model developed at one institution needs evidence from other settings. Different populations, measurements, and clinical workflows can all change how it performs.

FedCareAI helps researchers run a shared workflow against local data. Agree on the inputs, compute at each site, and bring back the permitted outputs.

01

Define the task

Share a trusted model and a data contract: features, target, and expected computation.

02

Run where the data lives

Each collaborator checks their schema and runs validation or training in their own Python environment.

03

Return the outputs

Compare site metrics or combine compatible numeric weights. Raw datasets stay at each site.

LOCAL TERMINALPython CLI
# Check the local data contract
fedcare local schema-check \
  --data ./demo/site_a.csv \
  --contract ./examples/contract.json

# Evaluate without retraining
fedcare local validate \
  --model ./demo/model.joblib \
  --data ./demo/site_a.csv \
  --contract ./examples/contract.json

Local training → numeric weights

What can we learn
across sites?

Start from a shared model, train locally, then average compatible weights. Export the combined model for evaluation or another training round.

Explore supported models ↗
LOCAL TERMINALPython CLI
# Repeat at each participating site
fedcare local train \
  --model ./demo/model.joblib \
  --data ./demo/site_a.csv \
  --contract ./examples/contract.json \
  --output ./demo/site_a.npz

# Combine the sites' numeric updates
fedcare local aggregate \
  ./demo/site_a.npz ./demo/site_b.npz \
  --output ./demo/average.npz

Omitting sample counts uses equal site weighting.

03 / Know the boundaries

Local data.
Clear expectations.

Keeping datasets local is one part of responsible collaboration. Research teams still decide what can be run, shared, and concluded.

What stays local
Raw datasets. Validation runs locally and returns metrics rather than row-level predictions.
What can be shared
Validation metrics, numeric model weights, and agreed metadata. Numeric updates are visible to their recipient; secure aggregation and differential privacy are outside the current implementation.
What the library supports
Preprocessed tabular classification and single-target regression. Training supports Keras and fitted incremental sklearn linear estimators; other sklearn models can be validated.
